# Phase 12 Test Inventory & Verification Report (Part A1)

## 1. Explanation of the "2 Tests" Discrepancy in Phase 11.1

In Phase 11.1's test inventory, `crates/service` was reported as having **2** tests, compared to **28** in Phase 9 and **31** in Phase 11.

### Root Cause Analysis
This discrepancy was caused solely by a faulty reporting / counting method in the log parser, not by any removal of tests:
1. `crates/service` comprises multiple independent test binaries:
   - Library unit tests: `src/lib.rs` (4 tests)
   - Binaries unit tests: `src/bin/*.rs` (0 tests)
   - Integration test: `tests/excel_tests.rs` (7 tests)
   - Integration test: `tests/part_b_tests.rs` (4 tests)
   - Integration test: `tests/pipeline_report_test.rs` (1 test)
   - Integration test: `tests/service_tests.rs` (13 tests)
   - Integration test: `tests/trial_mode_tests.rs` (2 tests)
2. When `cargo test` executes, each test binary outputs its own test summary line:
   `test result: ok. <N> passed; 0 failed; ...`
3. A naive regex or dictionary assignment that matched `test result: ok. (\d+) passed` and assigned `crate_counts["exam-panel-service"] = N` sequentially overwrote the count with each subsequent binary.
4. Because `tests/trial_mode_tests.rs` happens to be the last test binary executed for `exam-panel-service`, its count of **2 passed** overwrote the accumulated total, yielding `2` instead of `4 + 7 + 4 + 1 + 13 + 2 = 31`.
5. No tests were deleted or missing in `crates/service`. All 31 tests (plus 1 in `generate_types.rs` under feature `typegen`) have been present and passing.

The counting script `scripts/test-inventory.mjs` has been committed to enforce per-binary summation across all crates.
